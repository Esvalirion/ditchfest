# Ditchfest Signs

Репозиторий: [theonrd/Ditchfest-Signs](https://github.com/theonrd/Ditchfest-Signs)
Прод: https://ditchfest.su (GitHub Pages, кастомный домен через `CNAME`)

Фронтенд сообщества **Ditchfest** — Trackmania-ивента, где мапперы делают карты
на общую тему, а сообщество ставит им знаки-оценки («signs») и голосует.

## Стек

- Чистый HTML/CSS/JS, без сборщика, без фреймворка, без npm-зависимостей.
- Хостинг: GitHub Pages, ветка `main`, деплой = пуш в `main`.
- Бэкенд — отдельный репозиторий на Cloudflare Workers (`tm-votes`), фронт
  дергает его только через `tm.api()`.
- Авторизация — «Login with Ubisoft» через Worker, сессия — JWT в
  `localStorage` (ключ `tm_token`), фронт только читает payload для отображения,
  подпись проверяет Worker.

## Структура

**Общие модули (`js/`):**
- `core.js` — ядро: `window.tm` — `WORKER_URL`, `api()` (fetch с Bearer-токеном
  и JSON), сессия (`getUser/login/logout/sessionExpired`), DOM-хелперы
  (`el`, `escapeHtml`, `param`, `message`). Подключается первым на каждой странице.
- `layout.js` — рисует шапку (нав + кнопка логина + логотип) и футер в
  единственном экземпляре для всех страниц.
- `achievements.js` — рендер бейджей достижений (тексты и флаги приходят с Worker).
- `background.js` — параллакс-эффект фона.
- `script.js`, `voting.js`, `onboarding.js`, `mapper.js`, `mappers.js`, `admin.js` —
  логика отдельных страниц.

**Страницы:**
- `index.html` — галерея «знаков» с фильтрами (единственная страница со
  статическим контентом прямо в HTML, остальные строятся через JS).
- `voting.html` — все выпуски дичфеста аккордеоном, голосование «+» за карты.
- `onboarding.html` — пошаговое голосование для новичков (один выпуск на экране,
  прогресс хранится на сервере, в конце выдаётся ачивка).
- `mapper.html?id=<accountId>` — публичная страница аккаунта (ник, место в топе,
  достижения, карты); она же личный кабинет для владельца (там же logout и
  вход в админку, если админ).
- `top-mappers.html` — топ мапперов со ссылками на `mapper.html`.
- `top-players.html` — заглушка, ещё не реализовано.
- `admin.html` — управление админами.
- `roadmap.html` — открытый роадмап (RU), см. ниже.

**Ассеты:**
- `res/` — логотипы/иконки (`DitchFest_logo.svg`, `discord-sign-logo.svg`, favicon).
- `Signs/` — исходники «знаков»: фоны (`Backgrounds/`), бланки (`Ditchfest/`),
  оверлеи-стрелки/эмодзи и никнеймы участников (`Overlay/Names/`) — судя по
  всему, шаблоны для составления итоговых картинок-знаков вручную/генератором.
- `community_things/tm_signs_ALL.psd` — исходник в Photoshop.

## Роадмап проекта (из `roadmap.html`)

- **Быстрые фиксы:** ссылка на GitHub в футере.
- **Обычные фичи:** объединение мульти-аккаунтов, подпись темы дичфеста через
  админку, страница карты со ссылками на TMX/trackmania.io.
- **Крупные фичи:** вкладка Players (топ игроков, сбор рекордов), опенсорсинг
  бэкенда.
- **На обсуждении:** объединение карт по темам, бинго, интеграции с ботами,
  соцфичи (комментарии, подписки), статистика по онлайну.

## Особенности реализации (из `CLAUDE.md` репозитория)

- Каждая HTML-страница — скелет из `<div id="site-header">` + свой контент +
  `<footer id="site-footer">`; шапку и футер рендерит `layout.js` — их нельзя
  дублировать вручную в HTML (уже случалось расхождение).
- Порядок подключения скриптов фиксирован: `core.js` → `layout.js` →
  `background.js` → (`achievements.js`) → скрипт страницы.
- Все обращения к бэкенду — только через `tm.api()`, голых `fetch()` в скриптах
  страниц быть не должно.
- Только относительные пути — сайт должен работать и на `*.github.io`, и на
  `ditchfest.su`.
- Сайт полностью зависит от JS (кроме галереи на главной) — осознанный трейдофф
  ради отсутствия сборки/дублирования кода.
- Тестирование — локальный `python -m http.server`, либо jsdom-скрипт,
  прогоняющий все страницы без браузера.

## Что не найдено в репозитории

CI/CD-конфигов, тестов и package.json нет — весь процесс ручной. Бэкенд
(`tm-votes` на Cloudflare Workers) лежит в отдельном приватном проекте, в этом
репо не отражён.
